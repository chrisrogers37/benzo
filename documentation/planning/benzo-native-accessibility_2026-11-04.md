| **F5 — Confirmed misleading option copy.** | [SleepSetting:22–29][sleep-setting] and [appPresentation:4–9][presentation] promise “Full power-off, USB ports disabled,” “No background syncing,” “iPhone/Watch won't wake Mac,” and “No network wake — disables Find My.” The live demo displays them, including when options are editable. | A selected pmset preference is presented as a guaranteed physical outcome. For example, “Requests hibernation; USB power-off is not guaranteed” and “Disables TCP keep-alives; may limit Find My during sleep.” Review all five descriptions, without changing keys/defaults or adding hardware detection. #79/BZ-031 outcome acceptance stays with recovery/release. |

Colors are largely fixed light values; no explicit app appearance override or adaptive palette was found. | Check long errors/device names, enlarged supported text/display settings, low available screen height, and OS Light/Dark/Increase Contrast. The white panel alone is not a defect or justification for a new dark theme. Make local wrapping/scrolling/type adjustments only for a reproduced readability or access failure. |
| **F7 — State-announcement and parity limits.** | Native errors/results are ordinary changing Text; there is no explicit accessibility focus/announcement code. Add only missing semantics; add motion handling only if the system preference is not respected in native verification. Recovery labels, “Deep Sleep is On/Off,” restore meaning and quit uncertainty must come from the recovery owner, not from this plan. |

Ratios use the standard sRGB relative-luminance calculation for opaque source colors against `#fff`; hover/opacity/system-color rendering needs separate checking. Use **4.5:1 for ordinary text** and **3:1 for meaningful enabled controls/focus**, with applicable large-text/inactive-control exceptions, as practical targets for native and web review—not a claim of complete WCAG conformance. See [W3C text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) and [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).
